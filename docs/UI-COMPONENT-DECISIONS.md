## 2026-11-09：首页圆柱话题与 AI 先开场（已实现）

- 范围为 CHAT-04 / CHAT-14，沿用绿白、Nunito、当前抽屉和原生输入区。用户提供的 index.html / orbit.html 只作视觉与交互参考，未将参考中的说明或脚本当作额外任务指令。
- 选用只加载打包资源的 WebView 承载 CSS `perspective` / `translate3d`，而不是在 Compose 逐帧测量绘制 18 个文字层：用户明确要求 CSS 柱面透视，两份参考也可直接验证；Compose 继续拥有会话、请求、输入、状态和返回行为。未加第三方 JavaScript 库或远端资源依赖。
- 柱面前排保留局部切线角度，后排保持正字可辨并按深度降低透明度、增加模糊；关键词采用文字呈现，避免把环绕话题做成大片卡片。前排可点，拖动超过阈值后捕获手势并抑制点击；惯性采用时间积分，30/60/120Hz 速度一致。
- 选择会触发实际模型请求，因此使用受保护的聚焦确认层：完整话题、明确的“开启对话？”与“确定／取消”，避免重复标题和装饰性说明。背景 inert，焦点限制于确认层，系统返回／Escape 与取消一致。确认中的按钮禁用，防止重复请求；原生桥根据当前批次 ID 查找可信话题，不接受任意 JS 文本。
- 自转 6°/秒（每圈约一分钟），换批 900ms 快转；后台、输入、读屏、系统减少动效暂停；字体很大和高度很小时改为可滚动选择列表。选择与取消不产生付费请求。
- AI 开场将话题作为上下文数据，要求重新组织为一句自然英文问题；不伪造用户发言。开场话题随会话保存，取消／失败仍可重试或返回，首条回复重新生成继续使用话题上下文。
- WebView 禁止网络、文件与 content 访问、外部导航及弹窗。原生桥只暴露选择状态、换批、按 ID 确认和示例入口。API Key 与应用访问令牌均不传入页面。真实数据源仍为原有 440 条已审阅话题。
- 浏览器验证的是 APK 打包的同一份组件；不冒充 Android 原生覆盖安装、WebView 字体加载、TalkBack 或帧率验收。交付记录见 [首页改动](HOME-CYLINDER-2026-11-09.md)。

## 修改前后检查

修改 UI 代码或可见文案前，核对受影响组件；写完后按实际变化复查。小改动可在执行中简短完成，不强制先输出规格或等待批准。

| 检查项 | 完成依据 |
|---|---|
| 任务与选型 | 能解释用户目标、操作对象、内容长度与为何使用当前容器；不为了增加种类替换正常控件。 |
| 状态与恢复 | 只列适用的状态，明确提交、失败、重试和取消；简单本地选择无需虚构 loading。 |
| 模态与退出 | 说明背景能否操作，关闭／系统返回后回到哪里，输入法及编辑草稿如何处理。 |
| 文案必要性 | 按全局文案偏好和 DESIGN 检查新增或受影响的标题、标签、描述；保留影响操作决策与无障碍的信息。 |
| 平台与复用 | 使用当前 Compose 依赖支持的 API；检查共享组件消费者；Web 与原生分别验收。 |
| 事实与证据 | 清单同步到最终实现；候选不冒充已实施；明确哪些只读了源码、哪些已在设备验证。 |

必要时通过 UX/UI Agent Skills 比较组件语义、UI Layouts／shadcn 比较变体、UI UX Pro Max 查询平台问题、Impeccable 检查最终呈现。选择匹配问题的资源即可。

## 1. 先分清四个维度

| 维度 | 示例 | 需要确定的问题 |
|---|---|---|
| 任务语义 | 确认、编辑、选择、解释、通知 | 用户来这里完成什么？ |
| 容器与位置 | Dialog、Drawer、Bottom sheet、Inline | 内容在哪展示，是否保留背景？ |
| 模态性 | modal／non-modal | 背景还能不能操作？ |
| 状态 | loading、empty、error、success、selected | 当前发生什么，下一步能做什么？ |

Modal 是阻塞方式，不只指居中窗口。Bottom sheet 可有不同模态性。Loading 是状态，需要继续选择表现组件。不同库的 Sheet／Drawer 命名不完全一致，按实际行为映射。

## 2. 从 Web 词表映射到 Compose

| 参考词 | 场景 | 本项目可比较的原生方式 | 不应机械照搬的部分 |
|---|---|---|---|
| Dialog／Modal | 临时聚焦任务 | Material AlertDialog、自定义内容 Dialog | CSS 尺寸和 DOM 焦点代码 |
| AlertDialog | 重要确认、清楚解释后果 | Material AlertDialog，动作明确、初始焦点适当 | 不是所有操作都需要再次确认或输入 DELETE |
| Popconfirm | 就地、短内容确认 | 评估直接执行＋撤销，或明确确认 Dialog | 不必新增同名第三方浮层组件 |
| Drawer／Sheet | 导航、详情、辅助任务 | 导航 Drawer、ModalBottomSheet、独立详情页 | shadcn Sheet 通常指侧边面板，不等于手机默认选择 |
| Bottom sheet | 当前任务的选择、动作、辅助编辑 | ModalBottomSheet；持续辅助场景再评估其他 Sheet API | 不是所有长表单都适合半屏 |
| Popover | 锚定触发器的交互浮层 | 动作菜单可用 DropdownMenu；富内容另行设计 | Popover 与动作菜单并非完全同义 |
| Tooltip | 短解释 | 版本适配的 Material Tooltip API 或明确说明入口 | 手机核心内容不能依赖 hover |
| Inline alert | 与问题区域关联的持续提示 | 复用／扩展 InlineNotice、字段错误 supportingText | 不把长错误全部换成瞬时 Snackbar |
| Toast／Snackbar | 短暂反馈 | Snackbar，必要时带撤销／重试动作 | Web Toast 的定时和堆叠规则不直接套用 |
| Loading | 操作正在进行 | CircularProgressIndicator、LinearProgressIndicator、局部占位、按钮状态 | 不对所有控件强制套用同一等待动画 |
| Skeleton | 已知内容结构的加载 | 按当前依赖实现的占位组件 | 不复制 Tailwind animate-pulse 到 Kotlin |
| Disclosure／Accordion | 当前内容的渐进展开 | 状态提升＋AnimatedVisibility／条件内容 | 展开状态与数据加载状态分开建模 |

原生 API 的存在、参数和实验性标记以项目实际 Compose BOM 为准。

## 5. 状态只选适用的

| 类型 | 典型适用状态 | 不应强加的状态 |
|---|---|---|
| 本地三档单选 | closed、open、selected、dismissed | 无异步来源时无需 loading／error |
| AI 候选多选 | loading、empty、selectable、editing、saving、error、saved | 不将按钮 pressed 与整个流程状态混成一层 |
| 消息动作菜单 | closed、open、action unavailable、executing（如异步）、dismissed | 手机不需要依靠 hover 才能发现动作 |
| 场景编辑页 | clean、dirty、invalid、saving（若真实异步）、saved | 不用虚假的网络等待装饰本地保存 |
| 录音按钮 | idle、permission required、recording、cancel armed、processing、failed | 纯视觉变体不得改变录音／上传业务契约 |
