# 0.4.0 交互与提示词说明

## 积累入口

- 下方“收藏好表达”：打开空白编辑器，可选词汇 / 表达 / 话题，填写英文、中文释义、例句后保存；不调用 AI。
- 长按单条消息 → 识别好表达：只把这条消息送入专用提取提示词；候选预览、编辑、选择后加入复习库。
- AI 输出不会自动改动已保存条目，保存前仍由用户确认。

## 长按菜单

| 选中内容 | 选项 |
|---|---|
| 自己的文字/已转写语音 | 识别好表达、复制、优化表达 |
| AI 回复 | 识别好表达、复制、重新生成 |
| 蓝色提示 | 识别好表达、复制、重新生成 |

复制语音块时复制转写文本，不复制音频。录音尚未转写时，可先重试转写或补充文字。

## 蓝色提示

优化表达：保留用户真正想说的意思与事实，生成主版本、可选短版本与简短中文说明；不替用户编造经历，不评分。

话题语料：根据近期真实对话给出 4–6 条地道表达/搭配，各含中文释义和适合当前话题的例句。没有明确话题时说明这是小聊语料。

提示独立保存为 `role=hint`，不作为 user/assistant 请求发给聊天模型。获取后用户如果想使用它，需要自己发出新的表达；系统不会假装用户已经说过这些句子。

重新生成提示时使用生成当时的来源和上下文锚点。重新生成普通 AI 回复时使用它之前的真实对话；只替换选中块，后续消息保留，不自动改写后续分支。

## 专用提示词实现

- Android：`network/LearningPrompts.kt` 的 `extract`、`optimize`、`topic`。
- 浏览器：`server/public/learning.js` 的 `extractionPrompts`、`optimizationPrompts`、`topicPrompts`。
- 提取：单条输入，1–5 个目标，JSON 候选，要求所选 ID、释义、例句、学习理由；不概括全场、不推断发音。
- 优化：指定选中用户原话与必要的先前真实对话，限制不改变事实、礼貌、时态或不确定性。
- 语料：只用真实对话识别当前话题，要求 4–6 项，避免生僻堆砌、虚构用户事实和冒充对话。
- 后端 `purpose=learning` 使用适合短语集合的输出上限；提取 `purpose=summary` 为结构化 JSON，不再把普通短对话统一按摘要预算处理。

## 开放资源

详见 `resources/英语场景资料核查清单.md` 和 `resources/sources.json`。当前提示卡为模型生成内容，未导入这些资源，不能把它标成有资料来源的原文。用户核查确定后再进行样本清洗、审校和授权归属处理。
