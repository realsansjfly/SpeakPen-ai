# 聊聊、抽屉与设置 UI 方案

日期：2026-10-31。状态：待用户审阅；仅制作独立 HTML 原型，未修改 Android 或浏览器产品实现。

交互预览：[打开方案](../design/chat-ui-review-2026-10-31/index.html)。静态总览：[三屏并排](../design/chat-ui-review-2026-10-31/overview.png)。

## 问题定义

以下影响依据用户反馈和源码推断，尚无本轮设备测量数据。

| UI 问题 | 当前位置与表现 | 影响 | 推荐处理 |
|---|---|---|---|
| 历史入口与持续导航不匹配 | CHAT-01、LIB-09：从顶部打开居中历史列表 | 查找旧对话需要中断当前页，列表空间受限 | 左侧 75% 宽导航抽屉，直接展示历史练习；列表滚动，设置固定底部 |
| 常驻导航挤占练习空间 | APP-01：聊聊／复习／设置底栏 | 低频设置与高频输入占用同等常驻空间 | 建议移除底部导航，将积累库与设置移入抽屉；复习和练收藏仍从积累库进入 |
| 顶部层级过多 | CHAT-01/02/03：标题、模式和状态等叠放 | 消息区起点偏低，模式和操作不集中 | 单行：左抽屉、中间自由聊天／场景、右新对话。删除“开口聊聊”，移除顶部“练收藏”；正常连接和难度不再常驻，异常状态仍就地提示 |
| 设置结构和保存步骤偏重 | SET-01/08/09：多卡片、保存／撤销固定区和离开确认 | 反复确认，字段关系不够紧凑 | 从抽屉进入完整设置页；按范围、用途用列表分组；返回时自动保存 |
| 空态缺少开口线索 | CHAT-04：少量静态建议 | 难以找到想聊的话题 | 轻量三行慢速话题流；保留“让 AI 先开口”；触摸话题先填入输入框 |
| 输入周边常驻内容偏多 | CHAT-10/11：学习工具、输入切换和手势说明 | 输入功能与辅助操作竞争注意力 | 输入主行仅语音／文字切换、输入主体和中文求助；有消息时显示学习辅助行，文字输入时隐藏录音手势提示 |

## 推荐结构与使用频率

高频输入、切换模式、新对话保留在聊天页；按需找记录、复习和设置集中到抽屉。组件只增加承担持续导航的 Drawer，不额外增加菜单、浮动按钮和嵌套面板。

- 顶部模式使用互斥分段控件。新对话沿用加号图标与无障碍名称，触摸目标至少 48dp。
- 抽屉从左向右展开，手机上约 75% 可用宽度；余下区域为遮罩。顶部沿用真实 App 图标，显示“本机学习者”及本机存储信息。当前产品没有账号系统，因此不伪造头像、登录和云同步。
- 历史按时间分组，整行恢复对应会话，当前项有选中态；长标题单行截断，读屏保留完整名称；空记录显示简短空态，不填充示例历史。原型内历史均为明确标记的示意数据。
- 积累库置于历史上方，是为取消底栏补足既有入口的建议；“练收藏”退出顶栏，不删除功能或数据。
- 设置使用带返回箭头的独立页面。当前对话／新对话默认保持范围切换；表达难度直接成行，高级设置默认折叠；显示播放、服务、体验模式用分隔线分组。
- 对话保留用户绿气泡、AI 白气泡、蓝色辅助提示。优化表达仍位于源用户消息之后、AI 回复之前；话题语料在底部。原有折叠持久化和上下文隔离继续保留。
- 场景顶部保留可展开的目标进度摘要，展开后可查看依据和更正；只压缩呈现，不调整结束判定或统计规则。

## 状态与退出规格

| 对象 | 进入、操作和退出 | 异常与保护 |
|---|---|---|
| 抽屉 | 左上角打开；遮罩、向左滑动或系统返回关闭；历史点击后关闭并恢复会话。抽屉打开时背景不可操作，焦点限制于抽屉；关闭后回到触发按钮 | 录音中保持现有导航锁定；生成中的请求仍绑定原会话，不因选择历史回写到新会话。尚未发送的文本按会话保留，切换不静默丢失 |
| 设置范围 | 当前与默认分别编辑草稿，切换范围保留两边修改 | 当前设置仅用于该会话后续生成；默认设置仅用于未来新对话。历史和在途生成配置不改写 |
| 设置返回保存 | 顶部返回、系统返回采用同一路径：有更改则先保存再退出，无更改直接退出。保存中防重复点击 | 失败留在设置页，错误说明与重试可见，草稿保留。当前与默认保存不得部分成功后报整体完成。配对仍是显式连接操作，立即生效，不能因退出设置误连服务 |
| 输入法与后台 | 系统返回首先收起输入法，再返回设置。设置草稿需要可恢复；切后台保存本地编辑，重新进入时反馈实际结果 | 自动保存不能保证在操作系统强杀瞬间完成；实现需补进程重建和存储失败验证，不用原型的内存模拟代替落盘 |
| 切模式／新对话 | 使用现有会话创建和草稿保护逻辑。离开或切换不结束原场景，返回仍可继续 | 不新增手动结束按钮；原场景结束边界、自由续聊和成功去重语义不变。本原型的模式按钮只切换展示状态，不实现会话业务 |
| 服务／录音／学习动作 | 正式实现沿用现有请求、权限、取消、配对和错误恢复流程 | 原型仅保留位置及必要控件；未联网、未录音，不表示对应流程已验收 |

“退出自动保存”是本轮用户对上一批显式保存方式的新指令，仅变更保存交互，不变更独立会话配置。设置页不再常驻保存／撤销按钮或常规离开确认框；保存失败必须可见且可恢复。

## 动效方案

- 推荐话题来自本地维护的候选池，空白新对话随机排列，无需额外模型请求。原型每次新建会重新打乱。
- 三条横向话题流，约 60–68 秒一周期。只有空白自由聊天展示；不在场景、已有消息、输入、录音、抽屉、设置和后台持续滚动。
- 可暂停／继续；悬停或键盘焦点进入话题时暂停，触摸选中后停下并填入草稿，不自动发送。
- 系统减少动态效果时改为静态换行话题；读屏只读取一份可选内容，复制的循环片段不重复播报。
- 抽屉采用短距离正常导航过渡。没有背景光效、浮动插图、全屏动效或其他抢注意力的动画。

## 审阅重点

1. 是否接受取消底栏，将积累库与设置统一移入抽屉？这是本方案为腾出聊天空间提出的具体导航调整。
2. 三行话题流的密度和存在感是否合适？预览中可暂停比较静止状态。
3. 设置分组和“返回时保存”的方式是否符合预期？可勾选原型旁的“模拟设置保存失败”查看失败恢复。

## 本次验证与边界

独立原型已在桌面 Chromium、360px 和 390px 视口检查。`verify.py` 验证 75% 抽屉、焦点循环和 Escape、当前／默认草稿隔离、返回保存和重新进入、保存失败保留及重试、目标展开、点击话题填入后再发送、横向不溢出、减少动态效果与无 JS 异常，结果见原型目录 `verification.json`。已查看实际渲染的首页、抽屉、设置、对话截图。

Impeccable 扫描提示：审阅页选中项底色已调整以提高文字对比度；Tab 下划线属于分段导航指示，不按卡片内边距处理；持续横向滚动是本轮用户要求，保留但补暂停及减少动态效果。此扫描不是原生可访问性证明。

未构建 Android、未调用真实接口、未进行真机验证；原生抽屉手势、系统返回／输入法、TalkBack、大字体、保存落盘／强杀恢复、录音和设备动效性能需在方案确认后的实现批次验证。原型中的服务、依据更正和积累库只说明入口位置，不冒充完整产品流程。

## 确认后的实施批次

1. 抽屉与单行顶部、取消底栏并接回积累库，验证历史恢复和原请求归属。
2. 设置独立路由、列表结构和自动保存状态机，测试独立范围、保存失败、后台及返回路径。
3. 空态话题与动效、输入区压缩、场景摘要，检查减少动态效果、小屏和大字体。
4. 使用项目原构建脚本输出独立未配对包，再分别报告自动化、真实接口和设备验证；不自动提交、推送或发布。
