# 无域名的公网 IP HTTPS：核验记录

核验日期：2026-11-09。用途：SpeakPen 的 Ubuntu 24.04 / Nginx / 公网 IPv4 `47.118.51.5`，保留 Android 的 HTTPS 要求。

## 已核验事实

- Let's Encrypt 已于 2026-01-15 宣布公网 IP 证书正式可用，必须选 `shortlived` profile，有效期约 160 小时（6 天多）。不要求先购买域名。[官方公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/)
- 官方 2026-03-11 的 Certbot 教程给出 `--ip-address` 参数。该参数始于 5.3；**使用 webroot 验证必须 Certbot >= 5.4**。服务器现有 apt Certbot 2.9 不满足要求。[官方教程](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)
- 本次读取 Let's Encrypt [生产 ACME directory](https://acme-v02.api.letsencrypt.org/directory)，确认 `meta.profiles.shortlived` 存在；含义见 [profiles 文档](https://letsencrypt.org/docs/profiles/)。
- 本次读取 [PyPI Certbot 元数据](https://pypi.org/pypi/certbot/json)，最新为 **5.9.0**，要求 Python >=3.10，适用 Ubuntu 24.04 的 Python 3.12。读取官方 PyPI sdist 的 CHANGELOG 和 CLI 源码，交叉确认上述参数和 5.4 webroot 支持。未执行该源码。sdist SHA-256：`bf7d096c8b7e595d8c8dd2c1374db2bd11f53ea33d1748aaea805e81007710d8`。[5.9.0 元数据](https://pypi.org/pypi/certbot/5.9.0/json)
- Certbot 官方提供 [pip + venv 安装方法](https://certbot.eff.org/instructions?ws=nginx&os=pip)，例如 `/opt/certbot/` 隔离环境；该替代方法为 best-effort 支持。可使用单独 `/opt/speakpen-certbot/`，通过完整路径调用，避免系统 Python 包冲突。
- **IP 证书使用 `certonly --webroot`，不使用 `--nginx` 安装插件。**官方教程说明 nginx/apache 插件尚不支持 IP 安装，因此 Nginx 的证书路径和重载 hook 需自行设置。[官方教程](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)

## 建议执行流程

1. 本地保存当前 Nginx 配置备份。安装 `python3-venv`，创建独立 venv 并安装官方 `certbot==5.9.0`，用完整可执行路径调用。
2. 建立 ACME webroot，例如 `/var/www/speakpen-acme`。Nginx HTTP 80 的 `/.well-known/acme-challenge/` 使用该 root；其他路径仍转发当前服务，保证签发及后续续期不中断服务。
3. 从公网验证测试 challenge 文件可取，再执行官方形式的申请命令。可先用 `--dry-run`（staging）验证，再申请 production，防止把不受信任的 staging 证书装进线上。

```bash
/opt/speakpen-certbot/bin/certbot certonly \
  --webroot --webroot-path /var/www/speakpen-acme \
  --preferred-profile shortlived --ip-address 47.118.51.5 \
  --cert-name speakpen-ip --non-interactive --agree-tos \
  --register-unsafely-without-email
```

未指定邮件是一个主动选择；此处不虚构用户邮箱。若用户有管理邮箱，可改为 `--email 实际邮箱`。`--cert-name speakpen-ip` 明确指定下述目录名，避免依赖默认名字。

4. Nginx HTTPS 443 使用 `/etc/letsencrypt/live/speakpen-ip/fullchain.pem` 与 `privkey.pem`。HTTP 保留 challenge 路径，其余路径可跳转到固定 IP 的 HTTPS。
5. 为该 venv 的 `certbot renew` 配置 systemd timer（每天至少两次，建议每 6 小时一次，带随机延迟）及续期后 `nginx -t && systemctl reload nginx` 的 deploy hook。确认 timer 启用，执行 `renew --cert-name speakpen-ip --dry-run`。旧 apt 版 timer 不应再负责该新格式续期配置，避免两个版本竞争。
6. 从本机和外网使用正常证书校验访问 `https://47.118.51.5/health`，用 TLS 检查确认 SAN 为 IPAddress、签发者可信、到期时间符合短期证书。App 填 `https://47.118.51.5/v1`，无需开放明文网络或关闭证书检查。

## 边界

- 此记录为官方事实和执行建议，**不代表证书已申请成功、443 安全组已开放或续期已实测**；实际结果应由主任务的服务器执行记录补充。
- 必须维持 HTTP 80 的公网 challenge 可达和自动续期。证书有效期短，不能把一次申请成功当作长期可用。
- IP 变更时需要重新签发并更新 App 固定地址；公网 IP 由云平台分配，持有权通过 ACME 挑战验证。
