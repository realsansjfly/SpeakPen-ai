## 1. 产品判断与已确认入口

2026-10-26 用户确认：入口采用“简单（最轻松）”“日常（正常口语交际词汇、地道表达）”，并提供四级、六级、雅思等考试词汇及导入词库。此决定替代此前“简单／日常／深入”的三档提案；本次只更新规划，不实现功能。下面的组合方式与导入细节仍是设计建议，不代表用户逐项确认。

建议将入口统称“用词与练习目标”，在同一面板分组展示，而不是把考试名称硬排成能力阶梯：

| 入口分组 | 选项 | 建议行为 |
| --- | --- | --- |
| 日常交流 | 简单：最轻松 | 常用词义、短句、一次一个明确问题；表达仍自然，必要陌生词给简短解释 |
| 日常交流 | 日常：正常口语、地道表达 | 自然常见的词汇、搭配和句式；不为显示难度刻意堆难词或习语 |
| 考试词汇 | 四级、六级、雅思等 | 选择目标词库，以当前话题相关的少量目标词进行引导练习，不要求每句话都包含考试词 |
| 我的词库 | 导入词库、选择已导入词库 | 按用户目标练习，使用相同的选词、复习与反馈机制 |

产品内部建议分开保存“表达基调（简单／日常）”和“目标词库（可无）”。例如“简单 + 六级词库”表示用容易理解的句子引出目标词，不是自动升级句式难度；“日常 + 我的词库”表示自然交谈中练习自选表达。用户界面仍可一键选考试入口，并显示正在使用的词库与表达基调。默认“日常”、考试入口默认沿用当前基调，均为待体验验证的默认值建议。

语速独立于以上设置；不做强制首次选择页。CEFR 可继续用于内部选材、样例校准与离线评测，但不再把 A1–C2 或“深入”作为本轮确定的主入口。这里控制 AI 输出与练习目标，不认证用户水平。考试词库训练也不自动意味着考试题型模拟或成绩预测。

词库资源尚未选定：四级、六级、雅思候选清单需分别核查来源、版本、适用范围与使用许可，不使用无依据的“官方完整词库”标签。目标词库不是禁止表，基础连接词与必要场景词照常使用。每次练习先选少量相关目标，区分“AI 已示范”和“用户已尝试使用”，不因 AI 说过或用户只用一次就标成掌握。与场景无关的词不硬塞，可换场景或暂缓安排。

导入设计建议：首期支持 UTF-8 TXT（每行一个词或短语）与 CSV（expression 必填，meaning、example、tags 可选）；导入前预览，提示重复、空行、字段错误并允许取消。保存词库名、来源和版本，保留短语、不同词义及用户释义；数量和文件大小上限在实施前确定。导入内容视为不可信学习数据，不能成为覆盖系统规则的指令，不执行公式或代码；仅将当前练习需要的条目送入模型，不自动上传整库。未知词义应让用户确认，不静默补造。首期不承诺 Excel、PDF 或图片识别导入。

## 3. 分级资料：用途和使用边界

| 来源 | 可提供什么 | 推荐用途 | 使用边界 |
| --- | --- | --- | --- |
| Council of Europe CEFR 描述量表 [R1] | A1–C2 沟通能力、词汇范围、控制等描述 | 定义各档“能完成什么任务” | 是能力框架，不是按词数划档的官方词表 |
| CEFR-J Vocabulary Profile 1.5，经 Open Language Profiles 分发 [R2] | CSV 含 headword、词性、CEFR、部分主题字段；主体 A1–B2 | 首期本地词汇标签、选材和离线评测基底 | 仓库明确可免费研究/商业使用，需正确引用；不是中国学习者个体能力测量，词义粒度有限 |
| 同库 CEFR-J Grammar Profile [R2] | 带分级的语法项目 | 控制从句、时态与句式复杂度 | 仅部分翻译为英文，需整理；不要直接把词汇档位当语法水平 |
| 同库 Octanove C1/C2 扩展 [R2] | 高阶词汇标注 | 后续高级档候选 | 与 CEFR-J 主体授权不同，CC BY-SA 4.0；记录来源与衍生数据分发条件 |
| Oxford 3000/5000 [R3] | 3000 核心词 A1–B2，额外 2000 词 B2–C1；频率与教学相关性 | 人工校准、参考样例、外链查词 | 官方可查/可下载不等于可直接再分发全库；本轮未取得产品打包授权 |
| English Vocabulary Profile [R4] | 词、词义、短语、短语动词和习语的等级 | 避免“基础词的难义”漏检，人工选材 | 研究说明强调多义词不同义项跨级；不把公开浏览当成数据库再分发授权 |
| NGSL 1.2 [R5] | 2809 个通用高频词 | 高频度补充指标 | 不是 CEFR 分级；官方搜索结果标 CC BY-SA 4.0，但正文两次读取失败，实际导入前再核对下载文件和许可 |

本轮核实 CSV 字段，没有批量导入资料。CEFR-J 官方入口还列出 1.6，不能把此处有明确来源的 1.5 数据称作最新版，也不能自动把 1.5 分发许可推广到所有其他资料。[R6]

建议路线：先用少量人工审核的分级示例和输出规则建立体验；再接入具有明确使用条款的词表，做离线分析及选材；最后按实际体验决定是否做在线复杂度检测。不是先收集几千条词汇才有资格实现这个功能。

词表校验要处理词形还原、词性、多词表达、专名和用户指定目标词。查不到的词是“未知”，不能直接标为 C2。不同词表不一致时保存原始来源与标签，不硬合成一个“权威等级”。用户复习目标即使超出当前档位，也应保留目标表达并简化周围语境。

不建议每轮生成→模型判级→重写→再判级。这样增加延迟和费用，重写还可能改变原意。首期用生成前约束和离线抽检；在线仅对明显异常提供一次“换简单说法”，不默默改写已经播放的回复。

## 4. 当前模型参数可行性

当前配置与上次运行状态对应：`qwen3.7-flash-2026-07-15`，OpenAI-compatible Chat Completions，经本机 Node 代理。当前 `server/src.mjs::chatPayload` 只复制模型、消息、流式标记、输出上限，并强制 `enable_thinking=false`；不会透传客户端任意温度字段。Android `ApiProtocol.chatBody` 只组装 model/messages，`AiClient` 补 purpose/stream。

因此：资料层面可行；工程上必须改 Android 请求、服务端参数白名单和持久化，不能只做滑块就宣称生效。本轮未对运行中的账号/快照发送实验请求，以下是官方接口支持范围，真实效果仍需小样本验证。[R7]

| 参数/能力 | 官方接口说明 | 对 SpeakPen 的建议 |
| --- | --- | --- |
| `messages` 的 system 内容 | 支持角色和行为指令 | 优先做场景、双方角色、目标、风格、纠错策略；每轮保留配置，而非只发送一次开场白 |
| `temperature` | [0,2)，控制采样多样性；Qwen3.7 非思考默认列为 0.7 | 高级设置开放，命名“回答随机性”；不称“智能度” |
| `top_p` | (0,1]；官方建议与温度二者选一调节 | 高级调试，不与温度同时做普通用户滑块 |
| `top_k` | Qwen 扩展参数，候选 Token 数限制 | 默认不开放；不能照搬其他平台全部采样器 |
| `presence_penalty` | [-2,2]，正值降低重复、负值增加重复；Qwen3.7 非思考当前默认表列 1.5 | 内部实验重点，复习需要再次出现目标词，不应盲目增加防重复 |
| `repetition_penalty` | 大于 0，1 表示不惩罚 | 首期保持受控默认；并非与上项完全相同 |
| `max_tokens` / `max_completion_tokens` | 控制输出上限，非字数；当前文档建议新接入用后者，列支持 Qwen3.5-Flash 及之后型号 | 界面展示“简短 / 适中 / 详细”，提示词定长度、服务端上限控成本；迁移字段须兼容当前快照及回退模型 |
| `seed` | 尽可能复现，并不保证逐字相同 | 内部对比实验，不做学习设置 |
| `enable_thinking`、`thinking_budget` | Qwen3.7 系列支持思考开关及预算 | 日常对话继续关闭，复杂语法讲解/课后分析另评估；不能把打开它当无代价提升 |
| `response_format` | JSON Object 和 JSON Schema，官方当前列表含 Qwen3.7-Flash [R8] | 可提升表达抽取和复盘字段一致性，仍校验内容、截断、拒绝及网络异常 |
| `stop` | 遇指定序列停止 | 内部协议用途，设置不当会截断正常回答 |
| 上下文范围 | 应用选择发送哪些消息，不是独立的“记忆力数值” | 保存场景配置与简短摘要，限制最近历史，防长聊忘记角色 |
| `frequency_penalty`、Min-P、Mirostat 等 | 本轮未在当前官方兼容接口找到对应支持确认 | 不承诺支持，不从其他聊天客户端照搬发送 |

Node 目前直接发 HTTP JSON；Qwen 扩展参数在上游请求顶层，不应机械地再套 Python SDK 使用的 `extra_body`。

初始实验值可以选温度 0.4 / 0.7 / 0.9 做同题比较，而不是直接宣布它们分别等于严谨、自然、有趣。角色风格首先由场景提示词决定。保持其他采样器固定，再单独评估重复惩罚；复习任务的重点指标是目标表达被自然引出的比例。抽取任务独立使用低随机性配置，不能被用户自由对话的风格参数污染。

## 5. 场景配置比裸露的完整 system prompt 更优先

Cherry Studio 将角色提示词和参数保存为助手预设；SillyTavern 把上下文长度和采样配置作为高级控制。[R9][R10]可借鉴预设保存与会话管理，不必把所有技术选项搬进手机首页。

普通入口拟为“本次怎么聊”：

- 场景：咖啡店、校园社交、旅行、面试，或自定义。
- AI 角色 / 我的角色：例如店员 / 顾客。
- 本轮目标：点饮品、问无糖选项、完成结账。
- 用词与练习目标：简单／日常；考试词库（四级、六级、雅思等）或导入词库，可与表达基调组合。
- 互动风格：耐心引导、自然朋友、面试官；与难度独立。
- 纠错时机：结束后、必要时、逐句；默认避免打断。
- 回复长度与中文帮助：有清晰默认值，常用项优先显示。
- 自定义背景文字：允许中文填写；高级区才提供补充指令、温度和恢复默认。

配置设计：基础教学规则 + 本次场景/角色/目标 + 难度与反馈策略 + 复习目标数据 + 对话历史。目标词和自定义背景应当作有边界的数据，不允许覆盖计费、权限或输出格式规则。场景变更中途生效时提示“从下一轮开始”；保存配置快照，编辑模板不追改既有会话。切换场景可选择新建会话，避免旧历史持续把角色拉回去。

把预设绑定到本地会话即可，不必新增账号、数据库云同步或向量库。提示词长度应限制，保留语言求助和提示块不进入普通聊天历史的既有规则。用户自定义的是可编辑背景/角色，不允许删除系统必要规则。技术参数在服务端校验数值类型、范围和任务类别，回退模型不支持时明确降级而非静默假装生效。

## 6. 规划顺序与验收

第一批按顺序规划：简单／日常表达基调 + 场景角色配置 + 会话配置保存；随后接入来源许可已核查的考试词库，以及带预览确认的 TXT／CSV 导入。词库数量与资源可用性单独验收，不以无数据的空入口充数。借鉴队友的数据与提示词结构，不合并自动评分/调档逻辑。新建时不因打开配置就创建空对话记录。

第二批：场景任务目标、渐进提示、课后“原句→自然表达→再说一次”、收藏目标在新情境中复习。优先利用现有提示块、收藏库和录音回听。

第三批：高级调参、预设导入导出、会话摘要记忆；自动难度建议需有用户反馈数据后再评估。发音评分须接专用音频评测，不能用 ASR 转写或文本大模型假装测发音。

候选功能与已有能力的差别：

| 候选 | 具体新增体验 | 依赖/取舍 | 优先级 |
| --- | --- | --- | --- |
| 场景任务卡 | 不仅选择“咖啡店”话题，而是完成问价、提出偏好、确认订单三个目标 | 需维护少量审核场景，完成判断显示依据，不伪造客观分数 | 高 |
| 渐进求助 | 先提示关键词，再给句型，最后才显示完整参考句 | 扩展现有提示块；优先一次生成多级提示、按需展开，控制调用量 | 高 |
| 原句与优化句对照，再说一次 | 原句、建议改法、用户新录音并排回听 | 复用表达优化和录音；不要自动把转写差异判成发音错误 | 高 |
| 目标表达迁移练习 | 今天在咖啡店用的表达，明天在旅行场景重新引出 | 扩展已有复习对话和日程，目标 1–3 个，避免机械塞满 | 高 |
| 课后小结 | 只选 1–3 个有消息证据的改进点，用户选中才入库 | 不改变当前“收藏好表达”按钮打开空白编辑页的约定；另设会话结束复盘入口 | 高 |
| 点词/短语释义 | 针对当前句子的意思解释，支持“我已认识/还不会” | 需词义消歧与短语选择；词表标签只作参考 | 中 |
| 我的场景模板 | 保存场景、双方角色、目标和风格，下次复用 | 分享时仅包含模板数据，不能携带服务凭据或私密聊天 | 中 |
| 同题成长回放 | 隔一周回答相同问题，对比两次录音及表达 | 统计实际说话时长、复习使用情况，避免未经验证的“英语提升百分比” | 中 |
| 兴趣与连续话题 | 用户选择保留少量背景，让下次继续聊 | 必须可看、可改、可清除，不能让旧记忆污染新角色场景 | 中 |
| 实时打断/全双工通话 | AI 说话时可插话，接近真实通话 | 当前录音→ASR→文本模型→TTS 串行架构需大改，先不作为短期承诺 | 后续 |
| 发音音素评分、虚拟人口型 | 更细音频反馈或角色表现 | 需要专门能力、费用与验证；不因竞品有就优先堆叠 | 后续 |

粗略复杂度用于排序：纯参数转发较低，但教学效果评估不可省；会话配置和全链路等级为中等；可靠词义分级、自动适应为中高；实时通话和音素评估为高。不是按按钮数量估工作量。

建议先做 6 个场景 × 简单／日常 2 档 × 3 次生成的 36 组固定输入小样本评测（实施阶段执行）；再为四级、六级、雅思及自定义词库各选固定目标集，分别在两种表达基调下检查目标引出、自然度与用户使用记录，加入话题不匹配、短语、多义词、空词库和重复导入的测试：比较难词/未知词、句长、从句、自然度、目标完成、追问是否单一、是否保持角色和端到端延迟。再用约 10 名实际同学做短练习，评估听懂率、求助次数、继续说的意愿。温度实验另设同输入、同配置、只改温度，不能与等级同时改后归因。

工程验收覆盖：旧记录加载、跨会话配置隔离、重生成使用原配置或明确的新配置、切档期间在途请求结果归属、回退/取消不出现过期建议、话题提示与表达优化遵守档位、复习高阶目标不被删掉、无效参数拒绝、网络失败不丢草稿。模型采样无严格确定性，不以字符串完全相等测试语言质量。
