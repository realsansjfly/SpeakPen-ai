## R1 · Taskmaster：我最推荐先核查的场景对话源

- 官方入口：https://github.com/google-research-datasets/Taskmaster
- TM-1 数据/许可说明：https://github.com/google-research-datasets/Taskmaster/blob/master/TM-1-2019/README.md
- TM-1 格式样例：https://github.com/google-research-datasets/Taskmaster/blob/master/TM-1-2019/sample.json
- TM-2 内容/许可说明：https://github.com/google-research-datasets/Taskmaster/blob/master/TM-2-2020/README.md
- TM-2 按领域文件：https://github.com/google-research-datasets/Taskmaster/tree/master/TM-2-2020/data

TM-1 官方介绍为 13,215 段任务对话，包含咖啡、比萨、打车、电影票、餐厅预约、修车。TM-2 为 17,289 段，覆盖餐厅、外卖、电影、酒店、航班、音乐、体育。TM-2 的用户说话来自转写，而助理端是人工文字经 TTS 播放，不能把它称为全部未经处理的自然人录音。

**可取之处**：场景贴近本项目；有同一沟通目标的多种问答，可以抽取询问、确认、修改要求等表达。CC BY 4.0 的文本使用路径相对清楚。

**质量边界**：官方转写说明承认可能存在错字、不规范语法、停顿、口语缩写与人工修订。需要编辑审校；不能把整库当标准答案。原始航班/店名等事实也不应被当成当前真实资讯。

**建议你重点看**：选“咖啡点单”和“航班变更”各若干段，判断是适合真人沟通练习，还是过于像和客服机器人填信息；是否需要将过长问答改成 6–10 轮。

维护核查：仓库当前为 archived；默认分支最新提交 2024-03-19，README 更新而非新增数据。按固定数据版本取样，不推荐依赖其旧运行代码；本轮没有克隆或执行代码。

## R2 · MultiWOZ：适合设计完整旅行任务

- 官方入口：https://github.com/budzianowski/multiwoz
- 官方数据说明：https://github.com/budzianowski/multiwoz/blob/master/README.md
- 版本包目录：https://github.com/budzianowski/multiwoz/tree/master/data
- 许可：https://github.com/budzianowski/multiwoz/blob/master/LICENSE

原项目介绍约一万段、多领域人际文字对话，提供对话目标、轮次及状态等字段。官网提供多个纠错版本；版本之间的注释与声明应分别保留。**原仓库的 MIT 声明不能自动覆盖任何第三方再发布/衍生数据**。

**建议使用**：从“找酒店 → 询价 → 提出偏好 → 预订 → 请求交通”生成有明确完成目标的口语任务，抽取澄清和修正要求的表达，而不是简单让用户背全文。

**质量边界**：有任务未完整完成、标注纠错和数据库化回复；部分表达可能生硬。不要直接复用占位符、虚构电话/地址作为真实数据。

**建议你核查**：一个单领域餐厅任务和一个跨领域旅行任务；检查难度是否过大，是否需要把目标拆成初/中级两版。

维护核查：未归档；默认分支最新提交 2025-01-14。GitHub pushedAt 更晚不等于数据最近更新。本轮仅阅读元数据与说明，不运行仓库。

## R3 · SGD：适合任务结构与场景分支

- 官方入口/数据/许可：https://github.com/google-research-datasets/dstc8-schema-guided-dialogue
- 训练集及 schema：https://github.com/google-research-datasets/dstc8-schema-guided-dialogue/tree/master/train
- 许可全文：https://github.com/google-research-datasets/dstc8-schema-guided-dialogue/blob/master/LICENSE.txt

官方提供 20 个领域，含旅行、餐厅、支付、事件、天气等，并提供意图、槽位和说话动作。对话由模拟框架与众包改写产生；它适合系统化覆盖，不应宣传为完全自由的自然闲聊。

**建议使用**：借助场景目标组织“询问信息、确认、更换方案、拒绝、补问”的分支；先做酒店和餐厅，避免一次覆盖 20 域。

**许可边界**：数据为 CC BY-SA 4.0。引用/改编具体数据时保留归属、许可和改动说明，并按许可管理衍生内容。不能把“参考后经过 AI 改写”当作免除原许可义务的理由。

**建议你核查**：schema 是否让练习太偏交易流程；应用是否真的需要任务达成评估。若只要日常闲聊，可以降低此源优先级。

维护核查：当前 archived；默认分支最新提交 2023-08-07。作为静态数据候选保留，不作为活跃软件依赖推荐。

## R4 · Tatoeba：补充例句，不拼成假对话

- 官方入口：https://tatoeba.org/
- 条款：https://tatoeba.org/en/terms_of_use （6.2、6.5）
- 下载与字段：https://tatoeba.org/en/downloads
- 官方 API 搜索示例：https://downloads.tatoeba.org/api/search_dev_example.html

适合按关键词找例句、翻译对和作者/许可。下载说明提供作者、句子 ID、修改时间等字段；音频文件另外带录制者、许可、归属链接，许可为空的录音不能默认站外使用。

**建议使用**：为“表达歉意”“提出建议”“描述周末”补充短句；保留句子 ID、作者、原链接和逐项许可。先审校日常、现代、口语常用且语义清楚的英语句子，不因存在中英链接就默认中文翻译准确。

**质量边界**：众包、非连续对话，单句缺上下文，译文需核对；不要把几条例句拼接后宣称原生场景对话。声音和文本许可不能混用。

**建议你核查**：按 apologize / reservation / weekend 各检索一些候选，检查是否自然、是否适合目标年龄与程度。先只考虑文本，不导入音频。

本轮英文条款直连读取曾超时，条款核心段通过索引一手页面确认；导入前还需逐条核对来源与许可。

## R5 · Wiktionary：短语动词与搭配依据

- 词组入口：https://en.wiktionary.org/wiki/Category:English_phrasal_verbs
- 搭配入口：https://en.wiktionary.org/wiki/Category:English_terms_with_collocations
- 可核查例项：https://en.wiktionary.org/wiki/catch_up
- 许可说明：https://en.wiktionary.org/wiki/Wiktionary:Copyrights
- 内容使用说明：https://en.wiktionary.org/wiki/Wiktionary:Collocations

可以核查 `catch up` 等词组的义项、语法结构与使用情境；同一词组可能有多个意思。原创词条文本有开放许可，但词条中引用的第三方例句、歌曲、音频等可能有额外权利，不能全部按词条默认许可打包。

**建议使用**：核对 AI 的词组含义与搭配是否吻合当前场景，再编写适合学习者的教学说明。引用或改编词条内容保留来源版本/归属和相应许可；不要抓取引用段落当免费例句库。

**质量边界**：含古义、方言、粗俗语、罕用词，需以使用标签和具体义项筛选。它不是直接可用的“高频口语排行榜”。

**建议你核查**：catch up、check in、run out of 这类词组是否符合你期待的“固定搭配”颗粒度；决定保留原词义还是只给简单中文解释。

## 我建议的落地方式

先从 R1 + R2 建立 3 个小场景：咖啡点单、餐厅预约、酒店入住。每个场景人工审校后准备：一个任务目标、一组角色、8–12 个目标表达、2–3 段短参考对话。数量是建议，不是已导入的内容。

专题对话先做周末、旅行计划、爱好。用 R4 的筛选例句与 R5 的具体词义补足表达，不把单句来源当整段对话来源。R3 暂作为分支设计参考。

应用层分开保存：

```text
resourceId / sourceUrl / sourceVersion / author / license / modified
scene / communicativeFunction / level(editor-assigned) / targetExpression
referenceDialogue / example / usageNotes / reviewer / approvedAt
```

等级由人工或后续经过验证的流程赋予，不把语料源没有提供的 CEFR 当官方标注。保留源文本与编辑版本的关系，不把模型生成内容误标成来源原文。

对话时只检索本场景已经审核的少量材料；模型根据目标推进角色扮演。蓝色“话题语料”若以后引用这些内容，应增加来源标注；当前 0.4.0 的提示卡是模型生成，尚未使用上述五源。

## 请你核查的决定

1. 场景对话是否优先采用咖啡/餐厅/酒店这三个场景？
2. Taskmaster 与 MultiWOZ 的客服/助理式问答，是否符合你期待的沟通风格？
3. 第一批是否只用文本，不用外部音频？
4. 是否接受 CC BY-SA 来源的归属与衍生内容管理？若暂不接受，先降低 R3/R5 的直接导入优先级。
5. 确定想采用的来源后，再取小量样本清洗、审校、确认后导入。当前没有下载整库、安装或执行第三方代码。
