# 手机无法连接排查与修复 · 2026-10-18

## 本次实际原因

1. 本机 `127.0.0.1:8787/v1/status` 返回 200，阿里云服务端没有停止。
2. 手机旧入口 `cleaning-trance-commissioner-daniel.trycloudflare.com` 已不能解析；原转发进程仍在，日志反复报 `Unauthorized: Tunnel not found`。
3. 旧启动脚本仅检查 tunnel 的进程存在，未检查公网请求，所以复用了失效连接并输出成功。
4. 新域名建立后，当前网络的系统 DNS 同样返回 ENOTFOUND；阿里/腾讯的加密解析能查到公开地址。单纯重建并不能解决此网络的解析问题。
5. 0.3.0 App 的内置/已配对 URL 不会因电脑启动而自动更新，必须通过新入口重新配对。

## 已修复

- 启动前对本地带鉴权 `/v1/status` 检查服务身份、版本与可用状态。
- 公网带鉴权请求必须指向同一个 Node 实例，不能把进程存活当连接成功。失效时仅停止本项目拥有的 tunnel 并重建。
- 新连接通过实际请求检查后才更新配对文件、二维码与成功提示。启动失败时 CMD 不再打开旧入口。
- 互斥启动，避免重复双击创建并发进程；健康连接的二次启动保留相同 PID 和地址。
- 手机和检测工具仅在 trycloudflare 域名的系统 DNS 失败时，尝试阿里/腾讯加密解析；继续校验原 HTTPS 域名证书，不改系统 DNS、不关闭证书验证、不硬编码目标 IP。
- App 增加“偏好 → 服务连接 → 重新连接”，支持粘贴网页入口或 speakpen 配对链接。
- 网页增加“复制入口”，解决浏览器/微信不唤起自定义协议的问题；电脑入口提供可复制的完整链接。
- APK 升为 0.3.1，内置本轮已经验证的新地址；保留已有对话与复习库。

## 手机操作

1. 覆盖安装 `deliverables/SpeakPen-0.3.1-debug.apk`。
2. 电脑双击“启动口语服务.cmd”，等“手机公网访问与鉴权均已验证”出现。
3. 扫描新生成的“打开真实对话.html”二维码，手机页面点“连接 App”。
4. 若浏览器未唤起 App，点网页“复制入口”，到 App 的“偏好 → 服务连接 → 重新连接”粘贴。
5. 旧 App 已保存过配对时，也应执行这次重新配对；旧二维码不要继续用。

## 验证命令

```powershell
.\scripts\test-service-connection.ps1
node --test server/test/*.test.mjs
node server/diagnose-connection.mjs
node server/smoke-live.mjs
```

连接检查不调用收费模型；最后一条会消耗少量 API 额度。手机实体设备尚未连接，服务器和公网入口的检查不能代替用户手机网络验收。

临时隧道在电脑休眠、网络中断或平台回收后仍可能失效。本版启动脚本能检测并重建，但旧手机地址不会凭空更新。持续免配对使用需要稳定域名/长期隧道，或部署到持续在线服务器。
