# SpeakPen 评审复核与解决方案

日期：2026-10-26。对象：本地主项目 `da49086`（0.4.0 / versionCode 6），以及用户提供的《SpeakPen-评审报告.md》。报告中的建议作为待核实意见处理，不作为执行指令。

本轮交付：逐项复核、详细实施与验收方案、组员分支审查、原签名体验包的构建验证。没有在运行中的服务上轮换令牌、迁移数据库、切换域名或部署云服务器；这些实施结果不能由本文代替。

## 1. 结论与事实修正

产品下一步应先解决“独立设备授权 + 固定服务入口 + 统一签名发布”，再进行数据库与代码分层。不要把三项基础设施工作与难度功能、Room 迁移放进同一次发布。

| 报告观点 | 复核结果与处理 |
|---|---|
| 服务令牌编入 APK，可提取消耗额度 | 成立。运营商 Key 未打包，但服务令牌也是付费调用凭证；两者不能混为一谈。历史 APK 已被 Git 跟踪。 |
| `/app.apk` 公开、无需授权 | 不准确。当前路由位于 `authorized()` 之后，实际需鉴权；Git 中的历史 APK 仍可能暴露有效服务令牌。 |
| 隧道后基于 `remoteAddress` 的限流退化 | 成立。当前部署来源多为本地隧道连接，不能隔离设备。现有限流仍有全局保护作用，但不是每人额度。 |
| 空令牌时放行 | 成立。启动器生成令牌不能替代服务自身的默认拒绝。 |
| 数据没有 schema 版本号 | 不准确。`DataJson.write()` 已写入 `version: 1`；缺版本读取校验、迁移链和恢复交互。 |
| 数据解析失败后永久只读 | 当前实例确实停止写入；并非不可恢复，修复文件并重新加载可以恢复。真正缺少的是应用内可理解、可操作的恢复流程。 |
| 完全没有候选去重 | 不准确。`saveCandidates()` 已按类型和 trim/lowercase 内容去重，并做批内 distinct；仍缺归一化、义项区分、手动入口一致性及例句多样性。 |
| 从未真机验证 | 用户已确认现有版本通过；关闭这一旧问题，补写事实来源。新增 0.5.0 变速和调档需要增量验证。 |
| 只有 debug 发布、图标依赖过大 | 成立，需统一签名、R8 和实际产物检查。具体体积收益以构建结果为准。 |
| 命名隧道同时解决电脑关机 | 不成立。只解决入口稳定；连接器与 Node 仍要持续在线。 |
| Web 本地运行意味着不依赖外网 | 不能这么推断。只要使用远程模型，依然依赖互联网；本地 Web 可避免手机隧道，但无法消除模型网络依赖。 |
| 9 个 Kotlin 测试、4 个 Node 测试 | 这是文件数量，不是测试用例数，汇报时应分别写文件数与 runner 的实际用例数。 |

## 2. P0：撤掉 APK 中的通用授权凭据

### 目标与接口

APK 可包含固定的公开 HTTPS 服务地址，不包含共享令牌或阿里云 Key。首次使用通过一次性邀请码完成设备登记；后续每台设备有独立、可撤销的访问令牌。设备授权不等于账号登录，也不自动提供跨设备同步。

1. 运维在服务器本地/受保护的管理端生成一次性配对票据。二维码优先使用至少 128 bit 随机票据，5 分钟过期、成功一次即失效；不在公开页面自动签发无限邀请码。
2. 若必须支持 6 位码：限制同时有效数量，单码最多 5 次失败，增加部署全局与可信来源限速；多设备公开注册优先换 8 位以上码。6 位码不能直接当永久 Bearer 令牌。
3. 新接口 `POST /v1/devices/enroll`：校验票据，在同一事务中消费票据并登记设备，返回随机 256 bit 设备令牌与 deviceId。两次并发兑换只有一次成功。
4. 服务保存 token 的 SHA-256 指纹及 deviceId、issuedAt、expiresAt、revokedAt、lastSeenAt；高熵随机令牌可直接哈希存储，不保存明文。管理接口与模型请求权限分离。
5. Android 将设备令牌放应用私有存储，使用 Android Keystore 管理加密密钥；导出学习数据不带令牌。网页使用独立授权状态，不能借网页存储冒充硬件级防护。
6. 请求授权返回“已验证的设备身份”，鉴权结果交给限流模块；默认按 deviceId 限流，不让未验证的请求头伪造设备身份。令牌轮换后设备 ID 与额度保持稳定。
7. 保留全局每日额度和最大并发，再加每设备分钟额度、每日额度、并发上限；聊天/ASR/TTS 分开计量。当前 500 次/日是请求数保护，不是金额硬上限，还应配供应商预算/告警。
8. 没有配置授权存储或管理密钥时拒绝启动；受保护 API 对缺失/无效凭据一律 401。公共 `/health` 只提供最低限度健康信息，不返回敏感配置。

建议新增 `server/auth/devices.mjs`、`pairing.mjs`、`quota.mjs`；设备表与额度表用 SQLite 事务持久化。限流在当前单实例内存缓存可用，额度持久化防止重启归零；多实例部署前再引入共享存储。

### 升级顺序，避免误伤现有手机

先备份学习数据并发布支持设备登记的过渡客户端 → 给现有测试者登记 → 验证新授权和撤销 → 公布旧凭据停止日期 → 撤销旧共享令牌 → 停止分发旧包。

若确认出现正在发生的额度盗用，应立即撤销旧共享令牌，允许旧客户端短暂中断并引导重新配对。当前没有取证发现正在被盗用，不把风险描述成既成事件。

`app/build.gradle.kts` 删除令牌注入，`ManagedService.config()` 只使用已登记设备凭据；`scripts/build.ps1` 停止读取/注入 `connection.accessToken`。二维码生成器改成短期票据，不再生成可长期调用模型的共享凭据。浏览器配对、诊断脚本、APK 下载方式一并迁移。

`verify-credential-boundary.py` 当前把“服务令牌必须存在于 dex”当通过条件，必须反转该断言。扫描全部交付 APK、静态 HTML 与 Git 新提交；不要在检查失败日志中打印命中的凭据。

### 验收

- APK 全条目扫描：无运营商 Key、无通用服务令牌；仅提取公开 URL 无法调用模型。
- 空配置不能静默公开付费接口；无凭据/已撤销令牌返回 401，且没有上游请求。
- 两台设备 A/B：A 超限时 B 正常；全局预算触顶时都停止；重启不重置每日计数。
- 配对码过期、重放、穷举、并发兑换均被正确拒绝；撤销 A 不影响 B。
- 不直接信任 `X-Forwarded-For`。只有部署明确信任的反向代理才能提供来源信息；主授权额度仍按已认证设备计算。

## 3. P0：稳定部署与语音等待

### 推荐方案与替代方案

推荐：一台可持续运行、能稳定访问阿里云的云服务器 + 自有固定域名 + HTTPS 反向代理 + Node 常驻进程 + 持久化目录。小规模试用可从 2 核/2 GB 评估，容量以并发和压测结果决定。部署地域以目标手机到服务及服务到供应商的实测链路决定；境内部署域名按平台要求处理备案。

不购置云资源的短期替代：固定域名的命名 Cloudflare Tunnel + 当前电脑常驻。Tunnel 基础服务可按官方套餐使用，但域名、电脑电力和云算力不是一概免费；电脑关机仍不可用，不适合作为全天候产品的最终形态。

部署步骤：

1. 将 `server/`、环境变量模板与明确 Node 版本打包；不提交实际 `.env`。云端配置新的运营凭据/预算及设备授权数据库。
2. Node 仅监听 loopback，经 Caddy/Nginx 暴露 HTTPS；进程由 systemd 或容器 restart policy 管理。持久化设备、额度和备份，不把它们放临时容器层。
3. 反向代理对 SSE 禁用缓冲和响应压缩干扰，配置合理读超时；设置 `DISABLE_STREAMING=false`。不要让现有启动脚本重新强制写回 true。
4. 用 `/health` 做存活检查；管理员诊断查看 readiness 与上游连通结果。供应商短暂故障不应触发持续重启循环。日志脱敏、不记录音频和完整对话。
5. 手机通过固定入口登记设备，测试从 Wi-Fi 切到移动网络、服务重启、断网重连；最终关闭作者电脑，确认仍可正常对话。
6. 固定入口稳定后，不再在每次构建时注入临时域名；为服务部署配置增加 `local-quick` / `stable`，避免本机脚本覆盖云端策略。

### 分段改善等待，不能承诺零延迟

第一阶段恢复聊天 SSE，让“文字开始出现”更早。当前 Android 解析器已有能力；它改善首字等待，不会自动把整段 TTS 变成实时语音。

第二阶段按完整英文句子生成音频：文本流到达 → 句子分段器 → 最多 1–2 个并发 TTS 请求 → 按序播放；保留稳定句子 ID、缓存键和取消代次。取消/切对话/开始录音必须清空队列，不能串音。只对完成的句子合成，不能每收到一个 token 都发 TTS；限制片段数，防止请求费用放大。

第三阶段再考虑流式 ASR 或实时语音模型。它会改变录音、端点检测和服务协议，不与当前按住说话版的安全升级捆绑。

记录 `releaseRecording → asrDone → firstText → firstAudio → done` 时间，覆盖不同网络和 5/15/45 秒录音，报告 p50/p95 与失败率；目标如短录音结束后首字 p50≤2.5 秒、首音 p50≤4 秒仅是待验证的工程目标。先测瓶颈，再选模型，不把模型名称当延迟保证。

验收：真实公网客户端能在上游结束前收到首块；取消及时中止上游与播放；流断保留可重试状态；非 SSE 兼容回退仍有效；电脑关闭不影响云部署。对供应商故障设置总时限与熔断，不能每家等待完整超时后层层叠加。

Cloudflare 官方当前明确：Quick Tunnel 不支持 SSE，主机名会随创建而变化，定位为开发测试：[官方文档](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。

## 4. P1：存储迁移与数据恢复

Room 是合理目标，但“上 Room 后删除所有保护逻辑”不合理。损坏、未来版本、磁盘不足依然需要保护；禁止 `fallbackToDestructiveMigration()` 直接清空学习记录。

建议表：`sessions`、`messages`（包括 hintKind/sourceMessageId/revision/difficulty）、`session_targets`、`message_hint_contexts`、`review_items`，另设 `app_state` 保存当前会话。录音仍是应用私有文件，数据库保存受限的相对文件名，不存绝对路径。先对齐组员新增字段，再确定数据库 v1，避免合并后立即二次迁移。

迁移步骤：

1. 先补“导出学习数据”：JSON 元数据 + 可选原录音 + schemaVersion/appVersion/文件校验和，使用系统文档选择器导出。不得包含设备令牌、运营 Key、服务配对入口。
2. 旧 JSON 读入时校验 version；无版本作为 legacy；高于客户端支持版本则提示更新，保留原文件。仅能容错的条目隔离保存，不能悄悄吞掉所有异常再返回空库。
3. 校验 JSON、唯一 ID、引用与录音名称，复制旧文件为迁移备份；使用 Room 单个事务导入，迁移标记也写在事务中。
4. 成功后核对会话/消息/复习条目数量、引用与样本内容。保留旧文件作为只读备份；下次启动不重复导入；崩溃后事务回滚再重试。
5. 若失败，进入恢复页：导出原文件/恢复已验证备份/查看坏记录；用户明确选择新建空库时才新建，旧文件仍隔离保留。不要无限期用一份空内存对象假装已加载。
6. 定期备份与恢复由 Repository 统一管理。导入压缩包限制数量、大小和路径，防止 `../` 路径穿越；禁止导入包携带的服务授权覆盖本机授权。

验收：0.4 JSON、0.5 带 difficulty JSON、空文件、截断文件、重复 ID、未来版本、磁盘满、迁移中进程死亡、重启重复迁移、缺录音文件。确认旧记录不被静默清空，录音缺失只影响回听，不阻止文字记录读取。

工作量：若含迁移、恢复 UI、导出和真实持久化测试，应预留约 2–4 人日；不沿用报告“一天必定完成”的估计。

## 5. P1：统一签名、release 与体积

### 当前安装冲突原因

两版 `applicationId` 都是 `com.speakpen.app`，但 debug 默认使用每台电脑自己的 `~/.android/debug.keystore`。同源码、同 applicationId、相同 CN=Android Debug 均不保证证书相同。Android 通过签名验证更新身份，版本号调大不会修复证书不匹配。

当前本机 0.4.0 证书 SHA-256：

`7b0d36c386c7b1db1799d73fa41d67d80fce832d126e9a3ac31d8b1f223dff9f`

组员仓库没有 0.5 APK 和 release 附件，因此不能声称已测得她实际安装包的证书。用户手机提示 + 两人各自 debug 构建与此机制一致；可用 `apksigner verify --print-certs` 对实际文件补验。

### 三种合理策略

| 需求 | 方案 | 数据影响 |
|---|---|---|
| 现在保留现有数据，体验组员功能 | 把她的源码在原签名环境构建，验证证书与现有版完全相同，再以 versionCode≥已安装版更新。 | 正常覆盖保留沙盒数据；仍建议先增加导出。 |
| 两版并存，反复 A/B 比较 | 实验版 `applicationIdSuffix = ".lab"`，应用名改为“开口·实验版”，并检查深链冲突。 | 两个沙盒独立，旧数据不会自动复制，需导入导出。 |
| 长期多人协作发布 | 统一 CI/发布负责人持有团队发布 keystore，设置明确 release signingConfig；成员只提交代码与 PR。 | 新 key 不能直接覆盖现有旧签名；需签名迁移策略或导出导入。 |

不要通过卸载解决团队持续发布；当前 allowBackup=false，卸载可能丢失学习记录和录音。`adb install -r` 不绕过签名验证。重命名 APK、改 versionName、重新压缩都不能解决证书冲突。只拿到旧证书公钥不能签包，需要旧私钥。

从旧 debug key 迁到新 release key 应安排一次专门迁移：旧签名的过渡版先提供可靠导出；再安装新签名并导入，或评估持有旧私钥时的 Android 签名轮换及目标系统兼容性。不能把签名轮换当所有 Android 8+ 设备都通用的无缝方案。不要将 debug key 长期当生产发布私钥。

短期可由本机统一构建，避免把 debug 私钥传给所有成员。长期私钥加密备份、限制读取、不进 Git；CI 的签名作业只在受保护分支运行，禁止不可信 PR 读取 secret，保留产物摘要与证书指纹。

### release 与大小实施

增加 release signingConfig（路径与密码从本地私密配置/CI secret 读取），`isMinifyEnabled=true`、`isShrinkResources=true`，使用优化规则构建；未配置签名时明确失败，不能将 unsigned APK 当已发布包。

先启用 R8 测量，再视结果把常用 Material 图标转为少量本地 vector，移除不再使用的 extended 依赖。检查实际 merged manifest 与 APK：debuggable=false、没有不需要的 DUMP 权限、HTTPS 策略保留。R8 后必须复测 JSON、网络、语音和持久化，不能只看编译成功。

CI 发布门槛：单元测试 + lint + 后台测试 + assembleRelease + apksigner verify + versionCode 单调增长 + 凭据扫描 + 升级保留数据验证 + 体积记录。DUMP 是否消失以产物清单为准，不只靠“release 会自动去掉”的推断。

## 6. P2：跨电脑启动器

将硬编码作者机器的 pwsh 路径改成 PATH 中的 `pwsh.exe`，其次探测标准 PowerShell 7 安装目录；找不到则提示安装 PowerShell 7。不能直接换成 Windows PowerShell 5.1，因为脚本依赖 `[Convert]::ToHexString`、`SHA256.HashData` 等新运行时 API，5.1 不兼容。

若要支持 5.1，必须同时替换这些 API、检查 UTF-8/BOM、原生命令 stderr、进程与互斥锁等行为，再单独测试；首版建议明确 PowerShell 7+ / Node 22+，不做不完整兼容。

预检还应检查 Node/JDK/SDK 所需版本、cloudflared 是否存在且签名有效、配置是否存在；缺软件时给出可理解提示，不自动执行远程安装器。脚本用相对项目路径，所有路径正确加引号，启动失败不打开旧二维码。

验收：干净电脑/含空格及中文路径/PATH 缺 pwsh/仅 PS5.1/重复启动/启动失败/仅停止本项目拥有的进程。服务启动不应要求 Android SDK；只有构建 APK 才需要 JDK 和 SDK。

## 7. P2：ViewModel 分层与并发

398 行不是单独的判错依据；问题是网络、持久化、音频和会话状态的生命周期集中在同一类，0.5 又扩大了它。分阶段抽取，不先建立空泛架构层。

- `LearningRepository`：唯一学习数据入口、Flow、事务、迁移、备份；UI 不手动串联 `persistJob?.join()`。
- `ConversationEngine`：上下文构建、回复/重试/重新生成、hint 排除；请求携带 sessionId/messageId/revision。
- `VoiceSessionController`：录音→转写→回复、播放、TTS 缓存与取消；复用既有 SpeechController 平台适配。
- `LearningActions`：选块识别、优化、话题语料、候选确认，独立于真实对话上下文。
- `DifficultyAdvisor`：升/降档策略与本会话冷却，解决组员分支问题后独立注入。

保留已有取消代次检查；提取模块时不删除保护机制。后台回写在单一状态 reducer/线程上校验 sessionId + revision + operationGeneration；不让 ViewModel 清理后仍写入旧状态。

验收关注行为：请求中切页面/切后台/取消/重新生成/开始录音/重启，均不串会话、不误播、不丢原录音。每次仅提取一个职责，现有回归通过后再进行下一次。

## 8. P2：真实持久化与平台测试

`isReturnDefaultValues=true` 说明当前 JVM 测试可能静默取得 Android 框架默认值；它不是“所有单元测试无效”，但不能当 AtomicFile/SharedPreferences 已验证。

纯逻辑保留普通 JUnit；涉及设置、文件与平台生命周期增加 Robolectric 或 instrumentation；Room 使用真实 DAO/事务与 MigrationTestHelper，分别覆盖数据库升级与 legacy JSON 导入。平台相关验证需要模拟器/手机，不能由 mock 自证。

逐步关闭对真实框架调用的默认值兜底：先把平台依赖注入接口，剩余误调用框架时让测试失败。新增少量关键 Compose/设备用例覆盖长按菜单、录音权限拒绝/恢复、后台取消及变速播放。已有真机验收记录归档，不要求为每个纯文字改动重复所有设备流程。

## 9. P2：候选去重与例句质量

用统一 `ExpressionNormalizer` 覆盖手动新增、AI 候选和导入：Unicode NFKC、Locale.ROOT 小写、折叠空格、规范引号和末尾无语义标点；不能去掉改变意义的否定词或所有标点。先按 kind + normalized content 判断表达重复，再让用户选择复用旧条目/补充新义项，避免合并不同词义。

保留来源与用户编辑。对同表达同义项已有例句时，提示词提供少量已存例句，要求变化场景和说话意图；本地过滤完全重复后供用户确认。不要仅凭提示词声称永不重复，也不要每次失败无限重试付费模型。新增测试覆盖大小写/空格/缩写/不同义项以及跨入口一致性。

## 10. 实施顺序与决策边界

| 阶段 | 交付 | 建议人日，非承诺 |
|---|---|---:|
| A | 同签名难度体验包、评审事实修正、确定发布负责人 | 0.5 |
| B | 修正 0.5 降档/冷却/过期请求，补边界测试，合并功能 | 1–2 |
| C | 数据导出 + 设备授权 + 凭据扫描 + 旧令牌退役 | 2–3 |
| D | 固定域名云部署 + SSE + 真实公网延迟基线 | 1–2，不含域名/账号办理等待 |
| E | Room 迁移/恢复 + 平台持久化测试 + release 发布 | 2–4 |
| F | 分句 TTS 与模块提取，按瓶颈推进 | 2–4 |

可并行：域名/云资源准备与分支逻辑修复。必须串行：旧数据导出先于可能破坏升级连续性的签名切换；新设备授权上线先于常规退役旧共享令牌；迁移兼容组员字段先于 Room 初始 schema 冻结。阶段估计有重叠，不应简单当固定交付工期。

需要团队明确的是云资源/域名归属与预算、正式包和实验包策略、发布私钥保管人。代码准备和回归验证可以提前完成；这些决定不构成要求现在重新提供 API Key。
